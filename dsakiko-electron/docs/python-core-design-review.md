## 六项行为及讨论结果

### 1. 小剧场无需聊天文本即可生成，以及再次生成的范围

关联：RUN-02、RUN-03、CHAT-07、RUN-06。

Python 的 [start_generation](../../GPT_SoVITS/multi_char_main.py) 直接从 Chat 的小剧场配置构造生成命令；已有内容时先清空整段对话。生成器 [text_generator](../../GPT_SoVITS/dp_local_multi_char.py) 仅发送角色、情境及输出要求，不携带先前生成的聊天历史，并要求约十五段、日语台词及中文翻译。

已确认：小剧场保留非连续生成，根据情景生成一次，之后不继续输入、只重新生成。该限制由前端入口承担，后端不强制限制模式的未来用法；再次生成遵守最后 Turn 替换规则。只有情景的主动生成不应伪造用户文本；当前 createTurn 主要描述 UserSubmission，[InputSessions.prepareSubmission](../src/renderer/src/features/chat/input-sessions.js) 拒绝空输入，正式声明现为 generateScenario，不经 prepareSubmission。旧约十五段、日语及中文翻译可作为迁移配置讨论，不在此擅自固化成后端硬限制。

### 2. 同一次响应中的多个工具按什么顺序执行

关联：AGENT-05、TOOL-01 至 TOOL-06。

Python [ToolCallingAgentRuntime.run](../../GPT_SoVITS/chat/tool_calling.py) 按 tool_calls 顺序逐个执行，并追加对应结果。我们已讨论模型返回的分组、调用身份和三种执行模式，但这些没有同时规定工具之间的调度顺序。

已确认沿用调用列表顺序：sync 等本地执行完成，block-async 等交互完成，async 等可靠受理后即可继续下一个工具，不等其最终交互结果。例如同批“写入文件、读取该文件”仍依次执行。暂不为只读工具另加并行分类；这是执行顺序约定，不改变原响应的分组。

### 3. 格式修复失败后，是否把原始输出作为台词

关联：AGENT-04、AGENT-09、SET-02。

Python [display_unformatted_llm_response](../../GPT_SoVITS/qconfig.py) 控制一个实际存在的分支：[最终输出处理](../../GPT_SoVITS/dp_local2.py) 在格式修复仍失败时，可把原始字符串直接写成角色消息，赋默认情绪并继续语音流程。

已再次确认：保留有限格式修复，取消“将失败原文强行当台词”的兜底及其旧开关；如需留存原文，作为诊断材料，不进入 DialoguePart、语音或正式回复上下文。这是有意的行为差异。

### 4. 生成失败和保存失败后，哪些内容保留、重试哪一步

关联：CHAT-09、RUN-04、AGENT-04、AGENT-05、AGENT-09。

Python [错误处理](../../GPT_SoVITS/dp_local2.py) 有按标志回滚最新用户消息及附件的分支，而格式失败明确保留用户输入；[ConversationRuntime._finish_if_ready](../../GPT_SoVITS/runtime/conversation.py) 保存失败时报告内容仍在内存。Python 还单独区分 [ModelScope 临时限流和额度耗尽](../../GPT_SoVITS/dp_local2.py)，对前者有界重试。

已确认按阶段区分：受理前失败保留草稿；受理后失败保留输入、附件和已接受的过程记录；保存失败重试保存，不重新调用 LLM 或工具。不撤销已提交 reasoning 或工具副作用，模型请求重试与显式重生成分开；不要求持久化 running。

已确认的失败处理：

| 例子 | 应保留什么／重试什么 |
| --- | --- |
| API 配置缺失，尚未受理 | 拒绝创建 Turn，保留提交材料，不消费旧 async 队列。 |
| 输入已经受理，首次请求超时 | 保留该轮输入及附件，不自动删除；有界请求重试不新建 Turn，显式重生成才创建新 UUID。 |
| 提醒工具已成功，下一次模型请求失败 | 保留工具调用及结果，只考虑重试失败的模型请求，不重放整段 Agent Loop。 |
| 台词生成成功，保存遇到磁盘错误 | 保留内存内容并明确未保存；只重试持久化，不能用重新生成代替保存。初始提交必须保存才能受理时，初始保存失败不启动工具。 |
| 只有语音失败 | 保留已合法的文字，不把整轮对话视为失败；该句无声 ready 并附带音频错误，避免队列一直阻塞。 |

已确认 running／finished／terminated 表示执行生命周期，另记录错误原因：Agent Loop 不可恢复失败归 terminated，使该组未消费 async 结果失效；只发生语音或播放错误不取消整个组。finished 等待本轮语音和演出全部结算，详见下文。保存失败单独报告，暂停该 Chat 的新生成和历史修改，仍允许查看、停止和重试保存；保存恢复后解除限制，不重新执行模型或工具。已运行的任务仍需正常结算并保留结果。

### 5. 关闭语音是停止合成，还是停止播放

关联：TTS-04、TTS-08、RUN-07、SET-04。

Python [toggle_voice](../../GPT_SoVITS/dp_local2.py) 修改 voice_output_enabled／if_generate_audio；[ConversationRuntime.process_response](../../GPT_SoVITS/runtime/conversation.py) 据此跳过新台词合成。现有 Electron 设计中，回放 silent、guide.audio 为 null 和语音任务参数分别有意义，不能自动等同于全局语音开关。

已确认：语音开关在 Turn 开始时固定，修改只影响下一个 Turn；当前轮尚未产生的后续台词也继续用该轮设置。关闭时 Conversation 不发送自动合成任务，直接把无音频台词标为 ready 交给 Performance。此开关不隐式删除历史音频或补合成历史；即时静音和显式回放仍属于播放控制。

### 6. Python 历史如何变成 Turn 和嵌套 Message

关联：CHAT-02、CHAT-08、CHAT-09、AGENT-08、AGENT-10。

Python [Message 与旧格式读取](../../GPT_SoVITS/chat/chat.py) 采用线性记录，没有新设计的 Turn 身份和 assistant 响应容器；[ToolCallRecordMeta](../../GPT_SoVITS/chat/chat_meta.py) 使用 message_index 关联工具记录；[滚动摘要](../../GPT_SoVITS/chat/rolling_summary.py) 使用 summary_until_message_index。

已确认采用一次性、允许信息损失的导入转换：按用户输入边界初步划分 Turn，不要求恢复原始响应分组；保留可读原文，不伪造缺失 reasoning。默认形态、摘要边界和工具残缺信息按以下规则转换，导入后直接使用新格式。

具体不是读取 JSON 的问题，而是旧文件没有保存某些信息：

- `用户 U → 台词 A1 → 台词 A2 → 用户 V` 可按用户边界迁移成两个 Turn；但旧台词没有 assistant 响应容器身份，无法确定 A1、A2 来自同一次响应还是工具循环前后的两次响应。合成一个迁移容器只能是迁移约定。
- ToolCallRecordMeta 有 callId、message_index 等，但不是完整供应商报文；Python 对 raw_result_content 截取前 12000 字符。接受已有结果不完整，不为此追溯补全或阻止导入；导入适配器仍须产出符合新核心结构约束的记录。
- 若上述旧摘要覆盖到 A1，将摘要放到 A1 所属 Turn 的末尾，接受该 Turn 尾部如 A2 未被摘要涵盖、却从压缩上下文排除的信息损失；原存档文字仍保留。不强制重新压缩，也不因此启用原先关闭的压缩功能。这是旧数据一次性迁移的例外，不改变新生成摘要必须覆盖完整 Turn 的规则。
- 旧 Message 没有逐句 formId 时，导入采用对应 Character 的默认形态并写入新记录，后续即可按普通新记录合成；已有音频仍保留。角色资源不存在时沿用缺失资源警告，不凭空创建形态。

这些处理全部由导入适配器一次完成。新的核心模块只消费新格式，不长期保留 Python 字段、旧索引或默认形态的兼容转换分支。

## 两处已讨论设计的协议衔接

### 取消隐藏工具分类

关联：WORLD-05、WORLD-08、CHAT-02、AGENT-10。

Python [工具循环](../../GPT_SoVITS/chat/tool_calling.py) 把隐藏工具的调用及结果加入当前 LLM history，只排除面向用户的工具记录。修改前的 AgentTool.visibility 曾将 hidden 描述为“不产生聊天消息”。如果一份 AssistantMessage 同时包含普通工具和隐藏工具，简单删除隐藏调用或结果会改变原响应，或留下没有结果的调用。

已确认不再隐藏工具：所有工具统一记录调用及结果，不再按世界书工具建立隐藏分支。正式 AgentTool 已移除 visibility，所有调用/结果统一顺序交付。纯检索诊断仍只放 Turn.meta，不进入模型上下文；知识查询范围及启用条件仍由世界书配置决定。工具结果不会因为可展示就变成角色台词。

### 停止后留下未完成的工具调用，下一轮怎么构造上下文

关联：RUN-04、CHAT-02、AGENT-10。

已确认保留停止前接受的记录，但新的 ToolCallPart 与 ToolResultMessage 分离后，可能出现“一份响应调用 A、B，只有 A 返回”的存档。此前 DeepSeek 实验已经确认，缺少结果时至少当前测试的 AI SDK 路径会在 HTTP 前拒绝；这里只引用已完成实验，没有重新发请求。

建议为每个没有结果的调用补充统一错误结果，用原 callId 关联，不要求符合工具的成功结果格式。未开始的调用标记 not_executed；确认取消的调用标记 cancelled；外部操作可能已经发生但未收到结果时标记 outcome_unknown。补齐不重新执行工具、不推断外部副作用已经回滚。存档记录这是运行器结算的错误，不冒充工具真实返回。

已核对本地演示使用的 AI SDK：ToolResultOutput 支持 error-text／error-json，DeepSeek 转换器将其内容编码为 tool 消息；[官方类型文档](https://ai-sdk.dev/docs/reference/ai-sdk-core/model-message#toolresultoutput)也有相应定义。此处验证了类型和适配代码，未新增真实 API 请求，不能声称所有供应商已实测。

async 已可靠受理并返回 accepted 的调用已经有协议结果，后续取消／失败不补第二份 ToolResultMessage，也不触发新 Turn。只有可靠受理前的失败才作为原调用的失败返回。

## 忙碌互斥与完整完成状态

已确认同一 Chat 在本轮生成、自动语音和演出尚未全部完成时不受理下一轮，finished 表示整个 Turn 完成。未完成的 async 交互不属于此完成条件，否则它等待新 Turn 处理、旧 Turn 又等待交互，无法正常续聊。

| 正在进行 | 同一 Chat 的受理规则 | 原因 |
| --- | --- | --- |
| Agent Loop 生成 | 暂不受理另一次生成、手动压缩、编辑、删除、重生成；允许改下一轮设置、接收并排队 async 返回 | 当前输入固定；自动压缩如属本轮上下文准备，属于同一个操作内部阶段。 |
| 手动压缩 | 暂不受理生成或改写历史；可继续播放已有内容 | 压缩依赖固定文本；回放不改变摘要材料。 |
| 某句手动语音重合成 | 可回放旧音频、处理其他句；编辑／删除目标句时取消该任务并使结果失效 | 保护的是该句的音频绑定，不是全部历史。自动语音与生成本来就需要重叠。 |
| 只有本轮播放尚未完成 | 不受理手动或自动新 Turn；async 成功结果继续排队 | 等本轮整体 finished 后再批量消费当时已就绪的有效结果。 |
| 独立历史回放 | 不阻止新 Turn；受理新轮后停止相关临时回放 sequence，包括当前句 | 回放只消费已有内容，不使历史 Turn 再次 running；由 Conversation 协调 Performance 交接。 |

生成结束只表示一个内部阶段结束，Turn 继续 running，直到本轮自动语音和普通演出都完成或以明确错误结算。语音失败按前述规则无声 ready，播放失败也须结算对应任务，不能永久卡住 finished。BGM、驻留动作及 recurring transition 不计入本轮完成条件；待播普通内容清空后应清理本轮过渡动作。独立的历史回放或手动重合成不使已 finished 的 Turn 重新变为 running。

async 在整个 running 阶段只收集结果，包含生成结束后的合成／播放阶段；到 finished 且允许受理时才批量启动下一轮。不等待所有交互完成，也不改为 block-async。

历史回放抢占已确认：新输入须先通过校验和持久化受理，再停止回放并交接新演出，拒绝提交不打断现有回放。手动和 async 新轮统一处理。停止的是相关临时回放，不调用 stopTurn 终止历史来源轮次，不关闭常驻对话 sequence，也不清理其他 Chat 的演出。已停止回放的等待需结算，迟到回调不能覆盖新演出状态。

停止先使逻辑执行 terminated 并作废本组 async 回流；底层无法立刻取消的推理仍占用调度器资源直到实际退出，不能假装资源已经释放。原先“停止保留当前句”的规则不变。为衔接播放期间不提交的决定，建议该句播完前继续阻止新 Turn，但允许已停止后的显式删除／替换移除对应演出；这是尚待确认的停止后受理细节。不同 Chat 不共享历史写入锁；共享 GPU 的排队仍由 Speech 管理。只更新音频时必须合并当前记录字段，不能拿旧的整份 Chat 快照覆盖之后的文本修改。

## 其他尚未完全定案的细节

- 停止普通 Turn 后保留当前句时何时允许新提交，以及手动重合成的目标句保护。生成完成后仍播放的常规 Turn 已确定锁住提交；独立历史回放不锁住提交。
- 背景、布局、朝向已确定按 Chat 保存，BGM 按全局设置保存；其他字段在签名细化时补齐。多角色世界书私有知识隔离交给查询设计，本阶段不展开。
- 显式参考材料覆盖的范围和优先级。特别是“锁定某一句历史台词的参考材料”属于可选设计扩展，本次未找到它是旧 Python 已有独立能力的证据，不应把它当作迁移必做项。

已确认保留 editAndRecreateTurn，只允许最后一轮，并沿用人工可编辑输入的范围。语义是移除旧末轮、按编辑后的输入及当前配置创建新 TurnId／新组，旧组保持失效；早期原地编辑仍保留后文，不自动生成。接口已同步为未实现声明，受理失败保留旧轮和附件。

实现时应由 Conversation 一次受理完成：先校验新输入和目标仍是最后一轮，再协调旧任务／演出失效与记录替换；不要求调用方先删除再创建。新输入校验或受理保存失败时不丢失旧轮，新轮已受理后的生成失败则按前述规则保留新输入。不因删除而撤销旧工具已发生的外部副作用，也不能提前回收新旧输入共用的附件。

## 历史修改与重启的补充决定

- 已确认原地编辑、删除或回溯历史时，使该 Chat 全部未消费 async 结果失效，包含尚未返回的请求；已经写入历史的内容仍按原历史管理规则处理。音频重合成及背景修改等不改变对话语义的操作不触发此失效。
- 已确认重启按中断恢复：只恢复已保存内容，不自动续跑旧 Agent Loop、重放工具、恢复未完成交互或演出；缺少工具结果时采用通用中断结算。旧运行映射和请求资格不恢复，迟到回调拒收；持久化提醒独立按到期和补发规则处理。提醒等内部事件没有有效组时开启新组。
- 突然退出不保证有机会完成保存或取消外部操作，因此“相当于中断”描述的是重启后的受理与恢复策略，不承诺恢复未落盘内容或撤销已经发生的副作用。
