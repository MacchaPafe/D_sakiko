# Python 版功能需求与 Electron 接口覆盖清单

基线日期：2026-10-07。需求来自当前工作区的 Python 实现，覆盖普通聊天、小剧场、共用服务，以及桌宠、WebUI 和维护功能。本文用于确定迁移范围、补充缺失需求，再评估 Electron 接口是否足够；不直接决定每项旧行为都必须原样保留。

现有接口能够描述基本对话主流程，但尚不足以完整承接 Python 版。主要缺口是历史编辑、滚动摘要状态、情绪与形态对应的声音选择、世界书、正式设置契约和模型资源管理。

## 使用方式

每条需求有稳定编号，便于在讨论和实现说明中引用。直接编辑表格的“需求决策”和“实现说明”两列；需要展开时，在对应分类下添加按编号命名的说明。新增需求使用新的编号，不因删除或调整顺序而重排已有编号。

- 需求决策可填写：保留旧行为、采用新行为、调整后保留、暂缓、不迁移。初始统一为“待定”，不表示已经批准实现。
- 实现说明可填写：负责模块、数据结构、方法、配置作用域、生效时机、异常行为和验收条件。初始“—”表示尚未填写。
- 接口覆盖是设计评估，不是实现完成状态。审查接口的方法体留空；部分可运行原型存在于同目录其他文件中，见 [原型说明](prototype.md)。
- `metadata` 或通用回调只是承接位置；缺少字段语义、业务操作和状态规则时，仍标为部分覆盖。
- 本文是需求设计清单，不是实施 issue；后续拆分实施任务时遵循仓库 `.scratch/` 与 triage 约定。

| 接口覆盖 | 含义 |
| --- | --- |
| 已覆盖 | 公开数据结构、操作和职责已明确考虑到需求；不代表已经实现或通过验收。 |
| 部分覆盖 | 有承接位置，但关键字段、策略或业务操作尚未明确。 |
| 未覆盖 | 核心接口没有对应业务能力。 |
| 行为不同 | 新设计与旧实现存在可观察差异，需要决定保留哪一种行为。 |

| 对话相关度 | 含义 |
| --- | --- |
| 高 | 直接影响输入、生成、上下文或历史正确性；可选功能启用时也可能具有高相关度。 |
| 中 | 参与语音、演出或日常操作，但纯文字对话可独立运行。 |
| 低 | 主要属于资源制作、管理或应用维护。 |

相关度不等于实现优先级。表格中标注“高／中”的需求同时涉及生成语义和可选表现能力。
