# Live2D 方向动作组只表示真实方向能力

Live2D V3 归一化后的项目标准动作组保留基础 `{group}` 作为默认播放入口，方向变体 `{group}_L`、`{group}_C`、`{group}_R` 只在模型存在显式、非空的对应方向动作时写入；无方向动作不再广播成三份方向组。运行时仍可在请求方向组缺失时回退到基础组，但这种 fallback 不算方向动作支持；小剧场只在左槽模型支持 `L` 且右槽模型支持 `R` 时显示面对面动作朝向，并在当前模型组合不支持时把本次 payload 降级为 `screen` 而不改写用户偏好配置。

基础 `{group}` 按项目标准动作组逐组建立：按 2026-09-30 的调整，优先使用 `_C` 正面动作，没有 `_C` 时使用无后缀动作；不把 `_L/_R` 混入默认组。动作编辑器只展示归一化结果中真实存在的动作组，不为了编辑便利补齐空方向组；方向能力查询只统计持久 `model3.json`/`model.json` 动作组，不受预览或动态加载 motion 影响。归组规则变更仅作用于首次规范化，已规范化模型保留用户分组，不通过升级版本号强制重建。

标准动作组 fallback 也按方向隔离：基础组只从其他基础组补，`_L/_C/_R` 只从对应方向变体补；基础组和全局默认池都不使用 `_L/_R` 动作兜底。这样方向变体组一旦存在就代表真实方向能力，普通模式也不会因为缺少默认动作而随机播放侧向动作。

`IDLE`（待机时随机）参考旧版 V2 下载器，匹配 kime、nnf、smile01、wink、sleep、niyaniya、nf_left、nf_right 等动作；`idle_motion`（基础待机）仍优先匹配 idle。没有随机待机候选时才回退到基础待机等现有规则，避免把两个组都直接填为 idle。这里的 nf_left/nf_right 是动作语义名称，朝向仍以文件末尾 `_C/_L/_R` 区分。

云端 V3 下载器安装新包时，所有标准动作组均复用 V2 下载器的文件名前缀分类规则；去掉 V3 的 `mtn_` 等前缀后匹配，仍执行上述 C 优先与方向隔离。该选项仅用于下载器安装准备，不改变 V2，也不重建已安装模型或普通导入模型的用户分组。安装前保留完整动作索引、逻辑 ID 和演出配置，分组之外的动作仍可独立选择。

下载器的 `idle_motion` 基础待机只保留一个动作，优先 `mtn_idle01_C.motion3.json`，其次其他 C 方向 idle、无方向 idle；没有可用 idle 时才选一个 smile 或既有兜底动作。方向变体分别按同样规则只保留一个对应方向动作。`IDLE` 随机待机仍保留多个候选，不受该数量限制影响。
