# 短期保留本地世界书对话诊断

世界书运行时为每轮成功、失败或用户取消的请求只生成一份带 `chat_id`、`turn_id` 和格式版本的世界书诊断记录，检索候选、过滤与排序决定、实际发送给模型的内容、静默工具轨迹、格式整理前的模型回答和最终用户可见回答都来自同一次运行对象，不为显示、日志或导出重新查询或分别拼装。每次查询的内部 `RetrievalTrace` 直接记录最终实际选中的 entry UUID 与候选，诊断和检索验收读取这份身份追踪，不再按正文相等关系反向推断；entry UUID 仍属于已发布世界书条目和内部追踪，不进入模型可见 DTO。模型线程完成记录后通过现有结构化 UI 事件交给单一诊断存储模块；该模块以小型 `append`、`recent` 和 `export_chat` 接口隐藏内存上限、JSON 序列化、日志轮转、损坏行处理和按对话筛选。回复下方只展示本次程序运行内最近十回合的同一记录，不在重启后用不稳定的消息索引把旧日志重新挂回气泡。

世界书诊断默认写入与普通应用日志隔离的本地按日滚动日志，并在首次启用时明确告知相关用户消息、模型回复和世界书内容会被短期保存且允许用户立即关闭；之后可在配置程序的“个性化”界面修改全局记录开关。关闭持久化仍保留本次运行的十回合内存诊断，记录不自动上传，也不进入聊天历史。日志使用标准库的日轮转和约三天备份数量，不为精确七十二小时另造存储系统，写入失败也不得中断聊天。当前对话的世界书运行菜单只导出匹配该 `chat_id` 的记录，ZIP 包含筛选后的 JSONL、敏感内容说明和导出摘要，不复制未筛选的原始日志。
