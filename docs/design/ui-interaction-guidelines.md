# 界面与交互设计约定

设计和修改界面时遵循以下约定。选项数量规则适用于项目各端，单层模态规则和组件库要求适用于 Electron。

组件库要求：新编写 UI 时，应当尽量使用或改造 radix-ui 相关的 UI 组件。该组件库中没有的组件可以自行实现。

## 选择控件

选项数量按实际可选值计算，占位提示不计入。

| 选项数量 | 交互约定 |
| --- | --- |
| 少于 4 个 | 直接展示全部选项。单选可用单选组或分段按钮，多选可用复选框。只有一个可用值时直接显示该值。 |
| 4–10 个 | 按场景选择下拉框或直接展示。 |
| 多于 10 个 | 必须在选择控件内提供搜索。按显示名称匹配，有常用别名时也纳入搜索。搜索结果支持用方向键移动、用回车确认。 |

例如，服装目录直接展示「V2 / V3」两个选项，BanG Dream! 角色目录可按名称、别名或 ID 搜索。

## Electron 浮窗与确认

- 应用自行绘制的模态页面和对话框同一时刻最多显示一层。需要编辑或进入下一步时，在同一浮窗内切换视图。简单确认可在操作附近展开，保留相关内容供用户核对。
- 为子视图提供明确的返回或取消入口。返回时恢复原来的选择、滚动位置和键盘焦点。需要多步导航时，复用共享浮窗组件。 [DialogNavigator](../../dsakiko-electron/src/renderer/src/components/ui/DialogNavigator.jsx)
- 系统文件选择器等操作系统提供的原生界面可以照常调用。

## 操作与文案

- 短操作优先在当前上下文完成。例如，从舞台打开服装管理时保留舞台和对话。复用现有的浮窗、选择控件和主题样式，让同类操作在各处表现一致。
- 界面展示会影响用户决定的信息。服装目录以 V2 或 V3 标识模型版本，服务商名称可放在诊断信息中。按钮写明实际动作和作用范围，例如「换上」和「设为新对话默认」。
- 次要操作可以在悬停或键盘聚焦时出现。入口出现时保持布局稳定，例如角色卡片上的编辑入口出现时，卡片宽度、文字和展开箭头的位置保持固定。待确认状态和完成任务所需的入口应当可见。
- 高影响操作在提交前说明后果。例如，删除服装前显示受影响的对话数量，以及这些对话将改用哪套服装。

## 状态反馈与后台任务

- 后台任务有固定入口。离开页面或关闭浮窗后，运行中的任务继续执行。用户仍可从下载中心找到任务，并按任务状态暂停、继续、重试或取消。
- 按真实阶段显示状态。例如，分别显示「正在下载」「校验并安装」和「已就绪」。进度条复用应用主题色，并用文字标明状态。
- 在问题发生的位置说明发生了什么，以及用户接下来可以做什么。例如，版本目录加载失败时，在当前页签提供「重试」。

以上约定参考了 Jakob Nielsen 关于状态可见、易于识别、用户控制、一致性和错误恢复的可用性原则。选项数量阈值和 Electron 单层模态是本项目的具体约定。 [Jakob Nielsen 的十大可用性原则](https://www.nngroup.com/articles/ten-usability-heuristics/)
