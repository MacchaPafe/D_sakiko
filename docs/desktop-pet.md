# 原生桌宠

桌宠是单角色对话的另一种展示形态，复用当前对话、语音合成和 Live2D 演出。使用现有 PyQt5、live2d-py 和 pygame.mixer，不需要 Electron、Node 或 Qt WebEngine。

## 使用

在主窗口的设置中点击“切换为桌宠形态”或“切换为普通形态”。进入桌宠后，聊天窗口隐藏，原 Pygame 角色窗口退出；点击桌宠本体可以重新打开聊天窗口。拖动角色可以移动桌宠。

- 鼠标悬浮在角色上，右侧状态气泡下方出现键盘和麦克风入口。输入面板位于入口下方，回复字幕再排在输入面板下方，各层左对齐；组件宽度、字号和自适应高度规则保持不变。收起输入面板后，字幕上移到入口下方。
- macOS 与 Windows 的鼠标有效区域由角色当前画面的非透明像素、正在显示的按钮栏、输入面板、可滚动字幕及模型失败入口组成。其余位置允许下层窗口接收鼠标，包括角色轮廓外、侧栏下方空白、控件圆角和阴影、状态气泡与操作通知。鼠标从角色移向按钮时，透明间隙只保留悬浮入口，不拦截点击。隐藏的侧栏不再预留窗口宽度。
- Windows 默认角色尺寸按屏幕逻辑 DPI 补偿：150% 缩放且 Qt 尚未代为缩放时，基准渲染区从 380×500 调整到 570×750；Qt 已处理的缩放不会重复叠加。右侧输入组件不随角色基准放大，滚轮倍率上限仍为 1.6 倍，并受屏幕可用区域限制。“恢复默认大小”回到补偿后的 1 倍。
- 点击“输入”打开文本框；“＋”只添加图片，沿用原有模型视觉能力与上传检查。草稿文字、图片和上传状态与聊天窗口同步。
- 消息确认提交、已发送的文字和图片从草稿清除后，输入面板自动收起。发送失败或等待确认期间新增了草稿内容时，面板保持展开。
- 回复字幕在输入面板打开时仍然显示，位于面板下方；再次打开输入面板不会隐藏正在显示的回复。字幕文字各段保持水平居中，最大高度为缩放后模型可见轮廓高度的三分之一，超长内容可滚动查看。右侧各层随角色移动，缩放仍以角色下缘为锚点，不因透明窗口扩宽而偏移角色。
- 单击角色并松开鼠标后，输入面板收起、草稿保留；空闲时仍触发角色动作。拖动角色时输入面板保持展开，松手后可以继续输入。回复或录音期间单击只收起面板，不打断当前任务。
- 点击“语音”开始录音，再点一次结束。识别结果插入录音开始时的对话草稿，不自动发送。要取消内容，结束后手动删除即可。模型加载或识别进程失败时可以点击“重试”。
- 切到其他窗口时输入面板收起，草稿保留。录音仍继续，结束录音入口保持可用。识别完成不会把焦点从其他应用抢回来。
- 回复生成、语音合成、排队和播放期间，发送按钮变成“停止回复”；不能切换对话或展示形态。停止后声音和待播内容清除，迟到的合成结果不再播放。
- 桌宠使用聊天窗口当前选中的对话，切换对话后跟随更新。桌宠自身没有对话选择器。
- 点击没有语音的历史角色消息也可回放字幕、动作和表情，不调用大模型或重新合成语音。字幕在动作开始时显示，动作与阅读时间均结束后完成；聊天记录不重复追加。再次点击历史消息会替换当前回放，切换对话会取消当前回放；新回复生成及自动播放期间仍禁止这些打断操作。
- 右键选择“隐藏桌宠”或“退出程序”。隐藏后生成与播放继续；通过系统托盘恢复桌宠或打开聊天窗口。

桌宠形态下，关闭聊天窗口只会隐藏它。退出程序请使用托盘、桌宠右键菜单或原有退出命令。切回普通形态后，关闭聊天窗口恢复原来的退出行为。默认启动仍使用普通形态，不保存上次展示形态。

没有模型时保留可点击的角色身份和输入入口，回复音频仍可播放。明确指定的模型加载失败时显示失败状态，不静默改成默认模型。当前系统没有可用托盘时，不允许进入桌宠，以免隐藏后无法恢复。

## 实现边界

`runtime/conversation.py` 负责轮次、取消、分段 TTS 和播放完成状态；`runtime/drafts.py` 与 `voice_input.py` 负责按对话的草稿和录音识别。`runtime/single_character_performance.py` 负责单角色队列、声音、口型和动作，Pygame 窗口与 Qt 桌宠共用它。Qt 宿主在 `desktop_pet/`，调用 `live2d_support` 管理模型和上下文，不通过 `live2d_module.py` 创建桌宠。

`desktop_pet/input_region.py` 将点击范围与窗口显示范围分离，不使用会裁剪角色动作的窗口遮罩。显示期间约每 8 毫秒检查全局指针；macOS 切换 `NSWindow.ignoresMouseEvents`，Windows 在 Qt 的透明分层窗口上切换 `WS_EX_TRANSPARENT`，保留原有焦点策略。任意应用按住鼠标时暂停切换，避免角色拖动、文字选择或下层窗口拖动途中改变接收方。隐藏和销毁桌宠时停止轮询。

角色在绘制完成后缓存透明度图，按逻辑坐标映射 Retina/高 DPI 像素，以 alpha 大于 10 判断命中。鼠标位于角色画布内时最多每 50 毫秒更新一次，远离时停止持续 GPU 读回。首次画面尚未就绪或读回失败时回退到角色边界。此方案存在指针轮询与最近一帧轮廓的短暂延迟，系统忙碌或鼠标极快移动后立即点击时仍需关注边界行为；它不提供操作系统原生逐像素输入形状的原子保证。

Windows 协作者验收重点：在另一应用前台时首次点击角色外轮廓、字幕下方和控件阴影应落到下层；角色点击与跨边界拖动、字幕滚动、输入面板文字选择应正常；从下层开始拖动并经过角色时不应被抢走；隐藏恢复、换模型及 100%/150%/200% DPI 下均应复查。Windows 原生桌面行为尚未实测。

macOS 展开输入时，除将面板设为 key window，还显式将 Qt 的原生内容视图设为第一响应者，以激活 Cocoa 文本输入上下文。仅有 Qt 编辑框焦点和窗口键盘焦点不足以启用拼音组合输入。收起时通过原生窗口同步移出并无激活地恢复显示来交还焦点，不直接调用系统通知方法 `resignKeyWindow`，避免 AppKit 留下旧 key window 记录而使再次展开失效。

收起时先完成控件布局和宿主窗口缩窄，再交还焦点。桌宠原生面板显式关闭 AppKit 自动窗口动画，避免 Qt 工具面板默认的弹出动画与这次窗口尺寸变化叠加，造成模型瞬间横向拉伸；其他窗口的动画设置保持不变。点击其他程序时原生面板已失焦，不会执行移出/恢复显示，这也是原先两种收起路径表现不同的原因。

展开输入期间先完成控件显示、原生键盘焦点请求和编辑框聚焦，再恢复失焦检查，避免同步 Qt 信号重入状态刷新时提前收起。macOS 非激活面板统一由定时状态刷新检查原生键盘焦点，Qt `focusChanged` 的过渡通知不直接收起面板；真正切到其他窗口后仍会收起并保留草稿。普通 Qt 后端继续使用控件焦点通知。

`AudioGenerate.generate_audio_for_character_sync()` 仍是合成接口，增加可选参数以固定入队时的语速和停顿。WebUI 沿用自身运行时，本次没有迁移。

普通窗口和桌宠使用同一套逐段演出协议：语音合成完成后进入待播队列，由本段动作开始回调统一启动声音、桌宠字幕与聊天逐字显示。后续已合成的文本不会提前显示；当前段的声音、动作和文字显示全部完成后，下一段才开始，不额外插入固定段间停顿。聊天窗口隐藏时仍正常发送文字显示完成回执。同步针对每段的开始与完成，不是逐字口型对齐。

长语音保留多个动作：音频达到 6 秒时，动作结束后等待 2.5 秒，如果声音仍在播放，最多再追加两次动作；V2 从当前情绪动作组选择，V3 沿用本段独立演出选择并允许重新播放。追加动作不重播声音或文字，声音结束时仍等待最后一个动作完成。

收到 thinking 指令立即尝试思考动作，首次播放不受冷却限制；后续思考动作使用独立的 15 秒间隔，且等待前一个动作结束。普通待机间隔仍为 25 秒。语音合成重试失败时保留文字，无声音或播放失败段保留阅读时间；缺少动作、模型失效、回调丢失均有降级处理。动作结束回执超过至少 60 秒（长语音则至少音频时长加 5 秒）仍未返回时报告异常并释放动作等待。停止回复后，旧轮次的动作和文字回执不能推进新轮次。

语音识别使用独立的本地 Python 子进程运行已有 Whisper 模型，避免识别与主程序 Torch 原生库冲突；不下载新模型、不引入网络服务。录音流只有一份。退出时释放麦克风并有界终止 ASR、合成和渲染进程。

## 本次验证

2026-09-30 针对直接启动桌宠后首次展开立即收起的问题，补充焦点交接保护并统一非激活面板的失焦依据。74 项通用回归、6 项 Cocoa 原生回归通过。新增测试在旧代码下复现同步刷新中断展开、滞后 Qt 通知错误收起，以及已收起后重复交还焦点；另以独立 Cocoa 进程验证首次展开、注入滞后控件通知、真正原生失焦收起、重新展开与中文预编辑/提交。用户报告的完整冷启动症状尚未在隔离程序中自然复现，仍需实际启动验收。

2026-09-30 修复点击模型收起时的窗口动画与缩窄时序：71 项通用回归、5 项 Cocoa 原生回归通过，原生检查确认仅桌宠关闭自动窗口动画。另以 V2/V3 真实模型分别测试 0.6/1.0/1.6 倍缩放、有无字幕、模型点击/原生失焦，共 24 种场景；收起期间模型绘制尺寸、OpenGL 上下文和帧缓冲均保持稳定，窗口位置与草稿不变，反复展开后仍可原生预编辑并提交中文。点击路径使用 Qt 测试事件，命中结果固定以排除模型动作遮挡测试坐标；此次未做屏幕逐帧录像验收。

2026-09-30 修复 macOS 桌宠中文输入通道：验证 Cocoa 第一响应者、当前输入法上下文、原生预编辑与中文提交、候选位置查询，以及收起后重新展开仍能恢复输入，且不激活整个应用或移动窗口。70 项通用输入与桌宠回归、5 项 Cocoa 原生回归通过。另用实际桌宠组件重复展开验证；预编辑与提交通过原生文本客户端方法测试，尚未用物理键盘验收系统拼音候选框。

2026-09-30 在 macOS Cocoa 后端完成鼠标有效区域验证：V2/V3 真实模型、Retina 2 倍画布；使用系统窗口命中查询确认角色和字幕命中桌宠，透明画布及字幕下方命中下层窗口。另验证原生输入焦点、草稿保留、缩放锚点和隐藏恢复，以及 4 项原生面板回归。这里的跨进程验证采用系统命中查询，并非物理鼠标点击或系统事件注入；拖动保护与区域组合另有 Qt 自动化回归。Windows 复用相同区域判断，留待协作者进行原生验收。

本机测试按环境要求执行了：

```sh
uv pip install --force-reinstall ctranslate2==3.24.0 'numpy<2'
```

随后直接使用 `.venv/bin/python`。这个本地兼容性覆盖与当前依赖声明冲突，`uv run` / 自动同步可能重新安装较新的 CTranslate2；验证此环境时不要通过它们启动。此次功能没有更改项目依赖声明和锁文件。
